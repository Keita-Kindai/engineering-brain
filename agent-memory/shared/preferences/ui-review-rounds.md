# Shape of the feedback

UIの指摘は**箇条書き15〜25項目のまとめて1通**で届く。参考画像が別途貼られることもある。1項目は1文で、粒度がばらばらに混ざる。

- 大きい方針（「ダークモードを実装したい」）
- 小さい見た目（「×をホバーした時枠いらない」）
- 途中で撤回（「ごめん多分一括追加ボタンはあったな。なんでもない」）
- 実装済みの再掲（前のroundで入れたものが、確認前に再度書かれる）

**先に現状コードと突き合わせ、「すでに実装済み」「未実装」「曖昧」に仕分ける。** 実装済みを黙って作り直さない。曖昧なものだけをAskUserQuestionで詰めてから着手する。1 roundにつき2〜3回、4問ずつが実際に回った分量。

短い一文の裏に判断が隠れていることがある。「使用回数を廃止」は並び替えの選択肢が2つ重複する問題を連れてくる。**指摘を実装した結果どこが壊れるかを先に見つけて、それも質問に含める。**

# Recurring preferences

繰り返し同じ方向へ倒れた判断。次に迷ったらこちら側を選ぶ。

- **揃っていることが情報量より優先される。** カードの高さ、対象者・問題数・作成者名の縦位置は、中身の量にかかわらず全カードで一致させる。そのためにタイトルを1行で切り、タグ欄を2行に固定してあふれを `+N` にまとめた。
- **数値より色。** Difficultyの数値レンジをカードから外し、rating色のドット列だけにした。「min〜max」も、押していない段まで含んで見えるので廃止し、押した色をその数だけ並べる形にした。
- **説明できない数字は置かない。** 「使用回数」は何を数えているか言えないので列ごと廃止した。
- **操作の見た目は、実際の動きと一致させる。** 並び替えは挿入なので、落下先は行のハイライトではなく行間の線で示す。行を塗ると入れ替えに見える。
- **枠より色。** ホバーで枠を足すのをやめ、印そのものの色を変える。
- **画面の役割に合わないものは消す。** 作成画面から挑戦状態のトグルを外した。記録は詳細画面の仕事。
- **ダークは1案に絞らず両方出して選ぶ。** 13章案と14章案の両方を実装し、ヘッダーで切り替えられるようにしてから決めた。

# Verification expectation

**実際のブラウザで動かして、数値で確かめたものだけを「できた」と報告する。** 揃えたなら全カードの高さと各行のoffsetを測る。ドラッグを直したなら合成イベントで実際に落として並びを確かめる。screenshotだけでは足りない（[[visual-verification-must-be-browser-observed]]）。

検証で作ったデータは残さない。テスト用の問題セットやAC記録は消してから報告する。
